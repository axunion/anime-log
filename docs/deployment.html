アーキテクチャ概要

anime-log は Cloudflare Workers 上で動作します。Workers はサーバーレス関数で、世界中の Cloudflare エッジ（CDN ノード）で実行されます。データベースは同じく Cloudflare が提供する D1（SQLite ベース）を使用します。

Cloudflare Workers とは？
AWS Lambda や Vercel Functions と同様のサーバーレス関数です。Node.js ではなく V8 エンジン上で動作し、コールドスタートがほぼなく応答が速いのが特徴です。wrangler deploy で関数コードとアセットを Cloudflare のネットワークにアップロードします。

デプロイパイプライン

main ブランチへの push（または PR マージ）をトリガーに、CI と Deploy の 2 本のワークフローが自動実行されます。

ワークフロー全体像

PR を作成してから本番に反映されるまでの流れ
💻 ローカルで
コード変更
→
🔀 PR を作成 GitHub
→
✅ CI が実行 ci.yml
→
🔀 main にマージ GitHub
→
🚀 Deploy が実行 deploy.yml
📋 ci.yml（PR / main push）
1
checkout + pnpm install依存パッケージをインストール
2
wrangler.toml を生成テンプレから生成。DB IDはダミー値でOK（テストはminiflare使用）
3
pnpm checkBiome lint + vue-tsc 型チェック
4
pnpm testclient（happy-dom）+ server（miniflare）テスト
🚀 deploy.yml（main push / 手動）
1
checkout + pnpm install同上
2
wrangler.toml を生成本物の CLOUDFLARE_D1_DATABASE_ID を使用
3
pnpm check + pnpm test安全網として再実行
4
D1 migrations apply未適用の SQL を本番 D1 に適用
5
pnpm build + wrangler deployWorker + 静的アセットを Cloudflare にアップロード
⚠️
マイグレーションが先な理由
deploy.yml では必ず D1 migrations apply → wrangler deploy の順に実行します。逆にすると、新しいコードが古いスキーマの DB にアクセスしてエラーになる可能性があります。マイグレーションは追加方向のみ（カラム追加・テーブル追加）なので、古いコードが新スキーマの DB を読んでも問題ありません。

ビルド成果物

pnpm build（= vite build）を実行すると以下が生成されます：

出力先内容用途
dist/client/ HTML・JS・CSS などの静的アセット Worker がユーザーに配信するファイル群
dist/anime_log/ バンドルされた Worker スクリプト (index.js) + wrangler.json wrangler deploy がこれを読んで Cloudflare にアップロード

wrangler.toml の管理

wrangler.toml は Wrangler コマンドが参照するプロジェクト設定ファイルです。ローカル開発・テスト・デプロイのすべてで使われます。

なぜ gitignore するのか？

wrangler.toml には D1 の database_id が含まれます。これは技術的には秘密情報ではありませんが、リポジトリに直接コミットすると将来の運用変更時（DB を作り直すなど）に混乱しやすくなります。また、ローカルの設定と CI の設定を分けて管理する方が安全です。

wrangler.toml の生成フロー
💻 ローカル（初回 clone 後）
1. pnpm install 実行
↓ postinstall フックが発火
2. render-wrangler-toml.mjs が実行
・wrangler.toml が既存 → スキップ
・env 未設定 → ヒント表示
3. 手動生成（初回のみ）:
CLOUDFLARE_D1_DATABASE_ID=<id> \
  node scripts/render-wrangler-toml.mjs
🤖 CI / GitHub Actions
1. pnpm install --frozen-lockfile
↓ postinstall: env 未設定でスキップ
2. 明示的に生成ステップを実行
# deploy.yml 内のステップ
- name: Generate wrangler.toml
  run: node scripts/render-wrangler-toml.mjs
  env:
    CLOUDFLARE_D1_DATABASE_ID:
      ${{ secrets.CLOUDFLARE_D1_DATABASE_ID }}
生成前後のファイルの変化：
wrangler.example.toml（テンプレ・コミット済み）
[[d1_databases]]
binding = "DB"
database_name = "anime-db"
database_id = "__DATABASE_ID__"
wrangler.toml（生成後・gitignore）
[[d1_databases]]
binding = "DB"
database_name = "anime-db"
database_id = "abc123-実際のID"

シークレット管理

このプロジェクトでは 2 種類のシークレット管理が共存しています。混乱しやすいので整理します。

シークレットの種類と保存場所
🔐 GitHub Secrets（CI 用）

GitHub Actions のワークフロー内でのみ参照できます。ローカルからは見えません。

キー名用途
CLOUDFLARE_API_TOKENwrangler-action が Cloudflare API を呼ぶための認証トークン
CLOUDFLARE_ACCOUNT_IDCloudflare のアカウント識別子
CLOUDFLARE_D1_DATABASE_IDD1 データベースの ID（wrangler.toml 生成に使用）
登録場所: repo → Settings → Secrets and variables → Actions
🔒 Cloudflare Secrets（Worker 用）

Worker の実行時に c.env.XXX として参照されます。wrangler secret put で登録し、Cloudflare のサーバーに保存されます。

キー名用途
API_TOKENAdmin UI からの API 操作を認証するトークン。src/server/middleware/auth.ts で検証
登録方法: wrangler secret put API_TOKEN（初回手動・以降は変更時のみ）
💻 .dev.vars（ローカル開発専用）

.dev.vars はローカルの pnpm dev 実行時に Wrangler が読むファイルです。gitignore されています。

キー名用途
API_TOKENローカル Worker 用トークン。dev では何でも通るので任意の値でOK
PROD_API_TOKENpnpm restore CLI が本番 API を叩くときに使うトークン
.dev.vars の中身（例）：
API_TOKEN=any-local-token
PROD_API_TOKEN=本番のAPIトークン
※ .dev.vars.example にキー名のサンプルあり
💡
GitHub Secrets と Cloudflare Secrets は別物です
API_TOKEN（Worker が使う）は Cloudflare に保存され、GitHub Actions からは操作しません。CLOUDFLARE_API_TOKEN（GitHub Actions が使う）は Wrangler の認証用で、Worker のコードからは見えません。

初回セットアップ

ℹ️
以下の手順は 新しい環境に最初にデプロイするときだけ実行します。2 回目以降は PR を出して main にマージするだけで自動デプロイされます。
  1. Cloudflare アカウントにログイン 
    pnpm exec wrangler login
    ブラウザが開いて認証画面が表示されます。承認すると CLI がアカウントと紐付きます。
  2. D1 データベースを作成 
    pnpm exec wrangler d1 create anime-db
    出力の中に database_id = "xxxx-xxxx-xxxx" が表示されます。この ID を後で使います。
  3. Worker の API トークンを設定（Cloudflare Secret） 
    pnpm exec wrangler secret put API_TOKEN
    プロンプトが出るので、Admin UI で使うランダムな文字列を入力します（例: openssl rand -hex 32 で生成）。
  4. Cloudflare API Token を発行

    Cloudflare dashboard → My Profile → API Tokens → Create Token を開きます。

    設定項目値
    テンプレート「Edit Cloudflare Workers」をベースに使用
    Account scopeWorkers Scripts:Edit、D1:Edit
    Zone scope不要（このプロジェクトは workers.dev サブドメインを使用）
    作成後にトークンが表示されます（この画面でしか見られないのでコピーしておくこと）。
  5. GitHub Secrets に 3 つ登録

    GitHub repo → Settings → Secrets and variables → Actions → New repository secret

    Secret 名値
    CLOUDFLARE_API_TOKEN手順 4 で発行したトークン
    CLOUDFLARE_ACCOUNT_IDpnpm exec wrangler whoami で確認、または dashboard 右下
    CLOUDFLARE_D1_DATABASE_ID手順 2 で表示された database_id
  6. ローカルの wrangler.toml を生成 
    CLOUDFLARE_D1_DATABASE_ID=<手順2のdatabase_id> \
  node scripts/render-wrangler-toml.mjs
    wrangler.toml が生成されます（gitignore されているのでコミットしません）。
  7. main に push → 初回デプロイを確認

    main ブランチに push（または PR をマージ）すると deploy.yml が自動実行されます。Actions タブで進捗を確認してください。

    deploy.yml が以下の順で自動実行されます：

    check + test
    →
    D1 migration
    →
    build + deploy

    デプロイ完了後、Worker の URL（例: https://anime-log.<your-subdomain>.workers.dev）が表示されます。

  8. 初期データを投入（任意）

    .dev.vars に PROD_API_TOKEN を設定してから：

    pnpm restore \
  --url https://anime-log.<your-subdomain>.workers.dev \
  --data data/data.json \
  --history data/history.json \
  --yes-replace-all

緊急デプロイ

GitHub Actions が使えない場合（障害・メンテナンス等）は、ローカルから直接デプロイできます。

⚠️
これはあくまで 緊急手段 です。通常は PR → CI → main マージのフローを使ってください。

前提条件の確認

  1. wrangler.toml が存在するか確認 
    cat wrangler.toml
    なければ生成: CLOUDFLARE_D1_DATABASE_ID=<id> node scripts/render-wrangler-toml.mjs
  2. Cloudflare に認証済みか確認 
    pnpm exec wrangler whoami
    未ログインなら pnpm exec wrangler login で認証
  3. デプロイ実行 
    pnpm build
pnpm exec wrangler deploy

ローカル vs 本番の違い

項目 ローカル (pnpm dev) 本番 (Cloudflare)
実行環境 miniflare（ローカル V8 エミュレーター） Cloudflare エッジ（本物の V8）
データベース ローカル SQLite（.wrangler/state/v3/d1/） Cloudflare D1（クラウド SQLite）
API_TOKEN .dev.vars から読む（何でも通る） Cloudflare Secret から読む（wrangler secret put で登録）
wrangler.toml 手動生成またはpostinstall自動生成 CI が render-wrangler-toml.mjs で生成
静的アセット Vite HMR で直接配信 dist/client/ を Worker の assets binding で配信
マイグレーション pnpm db:migrate（ローカルに適用） deploy.yml が pnpm db:migrate:remote を自動実行

トラブルシューティング

deploy.yml が失敗する

症状原因対処
Error: CLOUDFLARE_D1_DATABASE_ID is required GitHub Secret が未登録 repo → Settings → Secrets に CLOUDFLARE_D1_DATABASE_ID を追加
Authentication error / 10000 CLOUDFLARE_API_TOKEN が無効・期限切れ Cloudflare dashboard で新しいトークンを発行し GitHub Secret を更新
D1 database not found database_id が間違っている pnpm exec wrangler d1 list で正しい ID を確認
pnpm check で lint エラー Biome / vue-tsc のエラー ローカルで pnpm fix と pnpm typecheck を実行して修正
テストが落ちる コードのバグ ローカルで pnpm test を実行してデバッグ

wrangler.toml がエディターで gitignore されていないように見える

.gitignore への追加と git rm --cached wrangler.toml の両方が コミットされるまで、エディターは引き続きファイルを追跡中として表示します。これは正常な動作です。変更をコミットすれば解消されます。

ローカル開発で wrangler.toml が見つからない

# database_id が手元にある場合
CLOUDFLARE_D1_DATABASE_ID=<your-id> node scripts/render-wrangler-toml.mjs

# database_id を確認する方法
pnpm exec wrangler d1 list

D1 のデータが消えた / 初期化したい

# ローカルのみリセット（本番は触れない）
pnpm db:reset    # ローカル D1 を消して再作成
pnpm dev         # dev サーバー起動（別ターミナル）
pnpm seed:local  # data/data.json から再投入
